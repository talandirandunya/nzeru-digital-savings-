# Railway Deployment Setup - Quick Start

## 📋 Complete Checklist for Railway Deployment

### Step 1: Prepare Values (5 minutes)

Generate these values before touching Railway dashboard:

```bash
# 1. Generate SECRET_KEY
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
# Copy output → DJANGO_SECRET_KEY

# 2. Generate strong password
python -c "import secrets; print(secrets.token_urlsafe(32))"
# Copy output → DJANGO_SUPERUSER_PASSWORD
```

Save these values temporarily (don't commit to git)

### Step 2: Add PostgreSQL to Railway (2 minutes)

1. Railway Dashboard → Your Project
2. Click "Add Service" → PostgreSQL
3. Railway auto-generates `DATABASE_URL` variable
4. Keep this tab open, you'll need the URL

### Step 3: Set Environment Variables (3 minutes)

Go to: Railway Dashboard → Your Project → Variables

**Add these 10 variables:**

| Variable | Value |
|----------|-------|
| `DJANGO_SECRET_KEY` | From step 1 above |
| `DJANGO_DEBUG` | `False` |
| `DATABASE_URL` | Auto-generated by Railway |
| `PORT` | `8000` |
| `DJANGO_SUPERUSER_USERNAME` | `admin` |
| `DJANGO_SUPERUSER_EMAIL` | `your-email@example.com` |
| `DJANGO_SUPERUSER_PASSWORD` | From step 1 above |
| `ALLOWED_HOSTS` | `savingsutl-production.up.railway.app,.railway.app,localhost,127.0.0.1` |
| `EXTRA_CORS_ALLOWED_ORIGINS` | `https://glittering-cobbler-1d32f6.netlify.app,https://yourdomain.com` |
| `EXTRA_CSRF_TRUSTED_ORIGINS` | `https://glittering-cobbler-1d32f6.netlify.app,https://yourdomain.com` |

**Optional variables:**
- `TZ` = `UTC`
- `DJANGO_LOG_LEVEL` = `INFO`

### Step 4: Deploy (1 minute)

```bash
cd backend
git add .
git commit -m "chore: prepare for Railway deployment"
git push origin main
```

Railway automatically deploys on push.

### Step 5: Verify Deployment (2 minutes)

1. Railway Dashboard → Deployments → Latest
2. Watch logs for:
   ```
   ==> Running migrations...
   ==> Creating superuser...
   SUCCESS: Superuser "admin" created.
   ==> Starting Gunicorn on port 8000...
   ```
3. No errors = ✅ Deployment successful

### Step 6: Test API (1 minute)

Get your Railway URL from the deployment card (looks like `https://xxx-xxx.up.railway.app`)

```bash
# Health check
curl https://your-railway-url/api/health/

# Login test
curl -X POST https://your-railway-url/api/auth/login/ \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<your-password>"}'
```

## 🔒 Security Reminders

✅ **DO:**
- Generate unique `DJANGO_SECRET_KEY` for production
- Use strong password for superuser
- Keep sensitive values in Railway dashboard (never in git)
- Update CORS origins to your actual domains

❌ **DON'T:**
- Commit `.env` files with secrets
- Use `DEBUG=True` in production
- Reuse local development passwords
- Share `DATABASE_URL` or `DJANGO_SECRET_KEY`

## 🐛 Troubleshooting Quick Links

- **Container restarting?** → Check logs for `DATABASE_URL` or `DJANGO_SECRET_KEY`
- **Static files not found?** → Already configured with WhiteNoise
- **Login fails?** → Check `EXTRA_CORS_ALLOWED_ORIGINS` matches frontend URL
- **Superuser exists error?** → Normal on re-deploy, safe to ignore
- **Database connection error?** → Copy `DATABASE_URL` from Railway dashboard
